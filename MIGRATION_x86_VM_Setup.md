## Part 3 — Bootstrap the x86 VM (fresh OS)

Target host: Ubuntu 24.04 or 26.04 LTS amd64, ≥ 8 GB RAM, ≥ 30 GB
free disk, sudo access.

### 3.0 One-liner (recommended)

```bash
curl -fsSL https://raw.githubusercontent.com/mbruyere/HLD-ARD-Network-Architecte/x86-migration/scripts/install_x86.sh | bash
```

Or with optional flags:

```bash
curl -fsSL https://raw.githubusercontent.com/mbruyere/HLD-ARD-Network-Architecte/x86-migration/scripts/install_x86.sh -o install_x86.sh
bash install_x86.sh --with-latex --with-claude
```

This runs Parts 3.1, 3.2, 3.3 and Part 4.1 + 4.4 in one pass:
installs Docker CE, containerlab, gh, Python venv with pinned
dependencies, clones all three repos under `$HOME/`, pulls all
container images, and builds the local images. At the end it prints
the three manual steps only you can do (`.env`, `gh auth login`,
`claude`).

If you prefer to do it by hand, the breakdown follows.

### 3.1 Base packages and Docker

```bash
sudo apt update && sudo apt upgrade -y
sudo apt install -y curl ca-certificates gnupg git build-essential \
                    python3.12 python3.12-venv python3.12-dev \
                    jq tree htop iputils-ping

# Docker CE (official repo)
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | \
  sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
echo "deb [arch=amd64 signed-by=/etc/apt/keyrings/docker.gpg] \
  https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list
sudo apt update && sudo apt install -y docker-ce docker-ce-cli \
  containerd.io docker-buildx-plugin docker-compose-plugin
sudo usermod -aG docker $USER && newgrp docker

# Containerlab
bash -c "$(curl -sL https://get.containerlab.dev)"

# GitHub CLI
sudo apt install -y gh
gh auth login   # follow browser/device flow
```

### 3.2 Claude Code

```bash
# Anthropic publishes a one-line installer; this matches the ARM setup:
curl -fsSL https://claude.ai/install.sh | bash
# OR if you have a private channel, use the same source you used on ARM.
claude          # first run: log in via browser flow
```

### 3.3 (Optional) LaTeX for paper builds

```bash
sudo apt install -y texlive-publishers texlive-fonts-recommended \
                    texlive-latex-extra latexmk
```

## Part 4 — Project setup on x86 VM

```bash
cd $HOME

# 1. Clone both repos
git clone https://github.com/mbruyere/HLD-ARD-Network-Architecte.git
git clone https://github.com/mbruyere/ibn-closed-loop-paper.git
git clone https://github.com/Cloud-Temple/graph-memory.git    # for ibn-graph-memory:local build

# 2. Check out the migration branch in the project repo
cd ~/HLD-ARD-Network-Architecte
git checkout x86-migration

# 3. Restore the .env (paste from your secure storage)
cp .env.example .env
nano .env                          # paste values from ARM .env

# 4. Python venv (use 3.12 — drop 3.14 oddities like the anyio MCP hang)
python3.12 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt

# 5. Build the local images (Phase 2 of x86-migration replaces these
#    with pinned/published versions; for now we keep parity with ARM)
cd ~/graph-memory && docker build -t ibn-graph-memory:local .
cd ~/HLD-ARD-Network-Architecte
docker compose build embedding-proxy
# NOTE: we do NOT build infra/frr-image/ on x86 — Phase 3 of the
# migration switches that to upstream frrouting/frr:10.3.

# 6. Pull pinned images
docker compose pull
docker pull ghcr.io/nokia/srlinux:latest
docker pull ghcr.io/sysoleg/vyos-container:latest
docker pull frrouting/frr:10.3
```

## Part 5 — Smoke test (x86 host)

```bash
cd ~/HLD-ARD-Network-Architecte
source .venv/bin/activate

# 1. Infra services
docker compose up -d
docker compose ps                  # all 4 services should be "healthy"

# 2. Unit tests (140 expected, no regressions)
PYTHONPATH=src python -m pytest tests/unit/ -q

# 3. Containerlab — deploy the topology
#    (no binfmt, no DOCKER_DEFAULT_PLATFORM — pure native amd64)
sudo clab deploy --reconfigure -t clab-ibnlab-switches.yml
sudo clab inspect -t clab-ibnlab-switches.yml

# 4. End-to-end pipeline run against one sample HLD
PYTHONPATH=src python -m ibn.pipeline.hld_commit \
    --commit "$(git rev-parse HEAD)" \
    --hld tests/fixtures/sample_hlds/hld_03_small_campus.md

# 5. Verify state landed
docker exec ibn-neo4j cypher-shell -u neo4j -p "$NEO4J_PASSWORD" \
    "MATCH (d:Device) RETURN d.deviceId, d.lifecycleState ORDER BY d.deviceId"
```

**Pass criteria for the smoke test:**

- All 4 compose services report `healthy` within 90 s.
- `pytest tests/unit/` → 140 passing.
- `clab deploy` → all nodes report `running` (no QEMU emulation needed
  for VyOS this time).
- Pipeline produces Neo4j Device nodes for the sample HLD.
